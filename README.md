# 🎲 骰子扰动 (Dice Query Perturbation)

给 SillyTavern 的向量检索注入随机变量：每次查询前 roll 一条意象短句拼进查询文本，
让查询向量发生语义偏移，从而打散 top-k 命中结果——同样的"我吻了他"，
这轮被一朵玫瑰染色，下轮被一场积雨染色，检索回来的语料跟着换。

只扰动查询，不碰入库，语料本身永远干净。

---

## 一、安装

把整个 `st-dice-perturbation` 文件夹复制到酒馆的第三方扩展目录。
两个可能的位置，**取决于你的酒馆版本**：

- 新版（1.12+）：`D:\sillytaven\data\default-user\extensions\st-dice-perturbation\`
- 旧版：`D:\sillytaven\public\scripts\extensions\third-party\st-dice-perturbation\`

不确定的话先放新版路径；如果扩展列表里没出现，再试旧版路径。

然后：重启酒馆（或刷新页面）→ 顶栏「扩展」面板 → 找到「🎲 骰子扰动」。

## 二、验证它在工作

1. 按 F12 打开浏览器控制台
2. 酒馆加载完成后应看到：`[骰子扰动] 骰子库已加载……` 和 `fetch 钩子已安装`
3. 在开了向量检索的聊天里发一条消息，控制台应出现：
   `[骰子扰动] 🎲 [天气] 积雨云压在楼顶迟迟不落 ×3 → collection: xxxx`
4. 设置面板里的「试掷一次」按钮可以随时手动 roll，确认骰子库读取正常

## 三、对照实验（确认扰动真实有效）

1. 找一个固定输入（比如"我吻了他"），关闭扰动（设置面板取消勾选），连发 10 次，
   记下每次向量注入的内容（酒馆的 prompt 查看器里能看到）
2. 打开扰动，同样输入再发 10 次
3. 对比两组命中分布：关闭时应该几乎每次相同；打开后应该明显散开
4. 如果打开后还是没散——**调大剂量滑杆**（重复次数），从 3 → 5 → 8 逐档试。
   剂量就是 roll 结果在查询文本里的占比，楼层文本越长需要的剂量越大

## 四、设置说明

| 参数 | 默认 | 说明 |
|---|---|---|
| 启用扰动 | 开 | 总开关，关闭即完全放行 |
| 控制台打印 | 开 | 每次 roll 打日志，调试期建议一直开着 |
| 先抽类目再抽条目 | 开 | 保证各类目出场概率均等，扰动方向铺满语义空间 |
| 剂量 | 3 | roll 结果重复拼接次数，1-10 |
| 排除前缀 | `file_` | 以此开头的 collection 不扰动。`file_` 是 Data Bank 文件库——设定、关系事实这类需要"贴"的检索受保护 |
| 白名单 | 空 | 非空时切换为白名单模式：**只**扰动包含这些片段的 collection。想精确到只扰动某个库时用 |

> 想知道自己各个库的 collectionId 是什么：开着日志聊几轮，
> 控制台每条记录末尾都会显示这次查询的 collection。

## 五、编辑骰子库（直接在设置面板里写）

v1.1 起骰子库就在设置面板的大文本框里，**打词儿就行，没有任何符号要求**：

```
## 类目名
一条语料
另一条语料

## 下一个类目
……
```

- `## ` 开头的一行 = 开一个新类目；下面每行一条语料；空行随意
- 改完**即时生效**，不用保存按钮、不用重启，存在酒馆配置里，云端和手机同样可用
- 「恢复默认库」按钮会用初始占位内容覆盖你写的东西，慎点
- `dice.json` 文件仍在扩展文件夹里，但只作为「恢复默认库」的来源，日常不用碰它

内容上的三条craft原则：

- **用短句，不用单词。** "玫瑰"两个字在几百字的查询里拽不动向量，
  "一朵开过头的玫瑰松了花瓣"才有剂量
- **骰子的词汇域要和被扰动的语料库大致重叠**，否则扰动方向没有语料呼应
- **类目在语义空间里铺开**，且注意"先抽类目"模式下各类目出场概率均等——
  想加重某个方向就多开几个类目去切它

这其实就是你给陆冀北做的那套散落细节——骰子库就是一个意象库，
往里面填东西的时候可以直接按你写状态栏"拾获"模块的感觉来。

## 六、已知限制

- `query-multi` 一次请求可能携带多个 collection 共享同一段查询文本，
  扰动是整体生效的：只要其中一个 collection 在允许范围内就会注入。
  日志里会完整列出本次涉及的所有 collection，方便你判断
- 酒馆大版本更新如果改了向量接口路径（目前是 `/api/vector/query`），
  需要同步改 `index.js` 里的 `isVectorQueryUrl` 函数——一行的事
- 本插件不会与原版 Vector Storage 冲突（不改它的任何文件），
  但如果装了其他同样包 `window.fetch` 的扩展，理论上有叠加顺序问题，
  实际一般相安无事

## 七、卸载

删掉文件夹，刷新页面。不留任何残余（设置数据会留在酒馆配置里，无害）。
